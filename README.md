# Підготовка даних спорів

## Актуальний запуск із кореня репозиторію

Код лежить у `src/`, а допоміжні команди — у `scripts/`. Для встановлення
модельних залежностей і запуску перевірок:

```text
python -m pip install -r requirements_comparison.txt
python scripts/run_tests.py
```

Підготовка даних із локального `dataset.csv`:

```text
python src/preparation.py --input dataset.csv --output outputs
```

Після завершення train-only дослідження фінальний вибір можна зафіксувати
без читання test, а потім виконати **рівно одну** фінальну оцінку:

```text
python src/train_only_study.py
python scripts/final_test.py --freeze-only
python scripts/final_test.py
```

Остання команда відкриває test і створює `final_test_outputs/test_report.json`.
Протокол та звіт незмінні: повторний запуск оцінювання зупиниться, аби не
використовувати test повторно для вибору моделі. Фінальний evaluator бере
стратегію з `train_only_outputs/selection.json`, повторно добирає параметри
лише на часових зрізах train, а test використовує тільки для звіту. Він не
зберігає рядкових прогнозів чи ID. Дані й виходи лишаються локальними.

Команди в наступних розділах — історичні інструкції експериментів; у цьому
репозиторії відповідні модулі розміщені в `src/`, скрипти — в `scripts/`,
а тести — в `tests/`.

## Зважене навчання, щотижнева стійкість і загальний звіт

`09_weighted_weekly_study.ipynb` — звіт нових експериментів, код —
`weighted_weekly_study.py`. Дві нові схеми ваг: сума та √суми, cap p99
визначається лише на відповідному train, середня вага дорівнює 1.
Для невідомої суми береться важливість медіанного train-спору, а не
вигадана сума для Score. Preprocessing незважений; ваги передаються лише
класифікатору. C обирається окремо, калібрування — лише за внутрішніми
out-of-time прогнозами. Score лишається звичайним незваженим доходом.

Щотижнева схема оцінює кожен тиждень 10–17 за попередніми тижнями.
Для cutoff t внутрішні фолди: (t−6, t−3) і (t−3, t); їхні оцінювані
частини завжди завершуються до зовнішнього тижня. Порівнюються 17 стратегій:
ЛР/калібрування, обидві ваги/калібрування, HGB/калібрування,
CatBoost/калібрування, два ансамблі, три interaction-варіанти, постійна
train-ймовірність і діагностичний фіксований C=0.1.

```text
python weighted_weekly_study.py --freeze-only
python -m unittest -v test_weighted_weekly
python weighted_weekly_study.py
python build_method_review.py
python check_notebooks.py 09_weighted_weekly_study.ipynb
python verify_weighted_weekly.py
```

Залежності — requirements_catboost.txt. Нові розрахунки читають лише
train_audit.csv; validation/test не відкриваються. Повний backtest
тривалий, тому notebook за замовчуванням читає результати після перевірки
хешів; RECOMPUTE=True запускає повне навчання. Незалежна перевірка рахує
Score всіх стратегій заново та перевчає моделі двох контрольних тижнів
свіжим Engine, без кешу початкового запуску.

Готовий загальний звіт — `method_review_outputs/method_review.html`.
`all_methods_overview.csv` містить стислий огляд, `all_methods_summary.csv`
— повні метрики й відносні оцінки. Окремо збережені три таблиці:
вкладений train, щотижневий train, попередній validation; також C-сітка
і ранні HGB feature-ablation спроби. Зведення validation використовує
тільки вже обчислену агреговану таблицю, без нових прогнозів або навчання.
Порожні оцінки означають «не оцінювали», а не нуль.

Щотижневі тижні 10–17 вже входили в попередні дослідження: це більше
часових зрізів, але не нові незалежні спори. Навчальні вікна перекриваються.
Оновлення щотижня припускає доступність попередніх won; без дат отримання
результатів перевірити це не можна. Ці обмеження збережені у висновках.

Підсумок зваженого навчання: вага за сумою дала 22 622.00 USD на 3
зовнішніх зрізах проти 22 732.60 у ЛР; вага √суми — 22 710.20 USD.
Калібрування цих ваг не допомогло. На 8 тижнях вага за сумою дала
-10.80 USD до ЛР, √суми +17.20 USD: практично суттєвої користі не отримано.

На щотижневій схемі номінальний максимум — CatBoost 18 170.20 USD
проти 17 850.20 у ЛР (+320 USD, +1.79%). Ансамбль ЛР+CatBoost —
18 155.40 USD. За попереднім правилом практичної близькості щотижнева
схема обрала простішу ЛР+PSP×currency: 18 075.00 USD, +224.80 до ЛР.
На 3 зовнішніх зрізах та сама взаємодія мала лише +44.80 USD.
Єдиного переможця в усіх режимах не встановлено.

81.75% тижневого приросту CatBoost і 94.31% приросту PSP×currency припадає
на тиждень 13. У групі PSP_B/EUR там 38 із 38 історичних спорів виграно,
тоді як середня оцінка ЛР — близько 25%. Це локальний груповий ефект,
а не один надвеликий платіж: найбільший окремий позитивний внесок — 17.20 USD.
Діагностика не використовується для післяфактум маршрутизації моделей.

Перевірки: 5 нових тестів, 48 незалежних грошових підрахунків,
повторне навчання всіх 17 стратегій для контрольних тижнів 10 і 17,
нормування ваг та часові межі. Проведено один повний backtest і два
контрольні повтори; це не два повні запуски. Notebook 09 читає перевірені
результати. Загальне зведення має 19 основних/історичних рядків,
окремо 5 значень C та 6 HGB feature-ablation спроб; усі відносні оцінки
перевірено через `verify_method_review.py`.

## Логістична регресія з взаємодіями

`08_logistic_interactions.ipynb` перевіряє провайдер × валюту,
провайдер × категорію причини й обидві взаємодії разом. Базові ознаки
збережено; взаємодії — додаткові категорії з train-only one-hot кодуванням.
Для кожного варіанта C окремо обирається з 0.01/0.1/1/10/100 на двох
внутрішніх часових зрізах. Зовнішні оцінювані періоди незмінні:
6–9, 10–13, 14–17. Очищення сум навчається заново на кожному рівні.
Validation і test у цьому етапі не відкриваються.

```text
python interaction_study.py --freeze-only
python -m unittest -v test_interaction_study
python check_notebooks.py 08_logistic_interactions.ipynb
python verify_interaction_results.py
```

Для звірки двох запусків перед повторенням збережіть копію
`interaction_outputs/run_evidence.json` як `first_run_evidence.json`.
Потрібні requirements_comparison.txt, train_audit.csv і попередні
train_only_outputs/ для звірки контрольної моделі. Нові результати —
`interaction_outputs/`: протокол, таблиці, зовнішні прогнози, внутрішні
кандидати, обрані C, покриття комбінацій, коефіцієнти та докази перевірки.

На однакових 5 141 спорах базова вкладена логістична має 22 732.60 USD;
додавання PSP×currency — 22 777.40, PSP×reason_category — 22 734.20,
обох взаємодій — 22 783.60 USD. Максимальний приріст 51 USD менший за
практичний поріг 257.05 USD, тому за протоколом зберігається baseline.
У контролю з фіксованим C=0.1 — 22 776.60 USD: від нього максимум вищий
лише на 7 USD. Цей фіксований C уже обирали після перегляду тих самих
train-періодів, тому його показано як діагностику, не незалежний кандидат.

Pooled log loss базової вкладеної моделі — 0.35157, PSP×currency — 0.32343,
обох взаємодій — 0.32409. Імовірності покращилися за log loss, але за
фінансовою метою немає практично суттєвого приросту в межах цього протоколу.
Результат не є незалежним підтвердженням майбутньої якості: train уже
аналізували, а дата доступності історичних міток невідома.

## Оновлена validation-таблиця та розбіжності моделей

`07_validation_and_disagreements.ipynb` додає CatBoost і нові train-tuned
стратегії до попередньої validation-таблиці. У цьому етапі validation
відкривається за запитом; test залишається закритим. Validation уже
використовувався раніше, тому нові числа не є незалежним фінальним тестом.

```text
python validation_extension.py --freeze-only
python -m unittest -v test_validation_extension
python check_notebooks.py 07_validation_and_disagreements.ipynb
python verify_validation_extension.py
```

Для звірки двох запусків перед повторним запуском збережіть копію
`validation_extension_outputs/run_evidence.json` як `first_run_evidence.json`.
Залежності — `requirements_catboost.txt`. Результати 03–06 не перезаписуються.

Нова об'єднана таблиця — `validation_extension_outputs/validation_summary.csv`:
усі п'ять старих рядків збережено, додано train-tuned логістичну регресію,
її калібрування, CatBoost, калібрований CatBoost та фіксований ансамбль.
Старий logistic має C=1, новий logistic_train_tuned — C=0.1, обраний тільки
на train. Для CatBoost train-вибір — depth=6, l2=10. Калібрування також
навчалося тільки на train out-of-time прогнозах. Параметри записуються
в `train_parameter_lock.json` до першого читання validation у розрахунковому процесі.

На 1 666 придатних validation-спорах train-tuned логістична має 7 234.20 USD,
CatBoost — 7 208.60 USD, їхній ансамбль — 7 237.20 USD. «Завжди» — 5 324.00 USD.
Повна таблиця містить також прирости, метрики ймовірностей, усі чотири тижні,
результат на 1 634 спорах без змінених USD-сум і покриття.

`pairwise_disagreement.csv` порівнює всі пари стратегій: різні класи при 0.5,
різні економічні дії, спільні/різні помилки й фінансовий внесок розбіжностей.
`decision_disagreement_groups.csv` розкладає Score за однаковими й різними діями.
`disagreement_details.csv` містить конкретні ID, ймовірності, дії, відому суму,
історичний результат і внесок у дохід для чотирьох основних пар.
Після незалежної перевірки `disagreements_lr_vs_cat.csv` містить тільки 28
спорів, де train-tuned логістична й CatBoost обрали різні бізнес-дії.

У цих 28 спорах: 20 рішень боротися лише логістичною дали 51.40 USD;
8 рішень боротися лише CatBoost дали 25.80 USD. Різниця -25.60 USD
повністю пояснює нижчий Score CatBoost. 22 із 28 розбіжностей мають хоча б
один прогноз очікуваного чистого доходу в межах 1 USD від нуля.
При класовому порозі 0.5 відповіді відрізняються в 40 із 1 683 спорів;
це інша кількість, бо правило бізнес-рішення залежить також від суми.

Розбіжності корисні для діагностики й перевірки ансамблю. Вибір «яку модель
слухати» за відомим won того самого validation-спору є витоком. Для нового
правила маршрутизації потрібне окреме навчання на train out-of-time прогнозах
і зовнішня перевірка. Такого правила тут не додавали; ваги ансамблю не підбирали.
Конкретні ID та виводи лишаються локально й не призначені для публікації.

## Додатковий кандидат CatBoost

`06_catboost_train_only.ipynb` порівнює CatBoost, калібрований CatBoost і
фіксований ансамбль із логістичною регресією на тій самій вкладеній часовій
схемі. Попередні train-only прогнози з ноутбука 05 повторно використовуються
після перевірки хешів, ID, сум і міток. Це не нові незалежні дані.
Validation і test не відкриваються, результати 03–05 не змінюються.

```text
python -m pip install -r requirements_catboost.txt
python catboost_study.py --freeze-only
python -m unittest -v test_catboost_study test_train_only_study
python check_notebooks.py 06_catboost_train_only.ipynb
```

Для запуску потрібні тільки початкові train-значення в `outputs/train_audit.csv`
і результати ноутбука 05 в `train_only_outputs/`. Нові виходи —
`catboost_outputs/`: окремий протокол, таблиці стратегій/періодів, калібрування,
внутрішні кандидати, зовнішні прогнози, моделі кожного зрізу та докази відтворення.
CatBoost 1.2.10 установлено в `.venv-win`; версія зафіксована окремо.

Чотири кандидати зафіксовано до нових результатів: depth 4/6 × l2 3/10;
500 ітерацій, learning rate 0.05, Ordered boosting, has_time=True, seed 42.
Параметри й калібрування визначаються лише всередині зовнішньої навчальної
частини. Категорії передаються як рядки, числові NaN не заповнюються;
набір ознак такий самий, як у логістичної регресії.
Критерій практичної близькості залишається 50 USD на 1 000 оцінених спорів.
CatBoost і HistGradientBoosting мають однаковий зафіксований рівень складності.

Алгоритми вибрано для перевірки різних припущень: проста адитивна логістична
модель, нелінійні дерева HistGradientBoosting, потім CatBoost із власною
обробкою категорій. Початково завантаження CatBoost зависло; тому його не
навчали в ноутбуках 04–05. Повторне встановлення для ноутбука 06 завершилось.
Жодна назва алгоритму сама по собі не гарантує кращого доходу.

На тих самих 5 141 придатних train-спорах CatBoost дав 22 739.80 USD,
калібрований CatBoost — 22 756.80 USD, ансамбль із логістичною — 22 800.80 USD.
Для звичайної логістичної регресії — 22 732.60 USD. Максимальний додатковий
дохід 68.20 USD менший за зафіксовану практичну межу 257.05 USD, тому
вибір за незмінним протоколом залишається за логістичною регресією.
CatBoost покращив pooled ROC AUC (0.86528 проти 0.84339) і log loss
(0.33107 проти 0.35157), але це не перетворилося на великий приріст доходу.
Результати є train-only порівнянням після попередніх досліджень, не
незалежним підтвердженням майбутньої якості.

## Додаткова перевірка лише всередині train

`05_train_only_nested_study.ipynb` виконує вкладене часове порівняння.
Вхід — тільки `outputs/train_audit.csv`; validation і test не відкриваються.
Код — `train_only_study.py`, результати — `train_only_outputs/`.

```text
python train_only_study.py --freeze-only
python -m unittest -v test_train_only_study
python check_notebooks.py 05_train_only_nested_study.ipynb
```

Альтернатива розрахунку без ноутбука: `python train_only_study.py`.
Залежності — `requirements_comparison.txt`. Для контрольованого використання
CPU можна задати OMP_NUM_THREADS=4 та OPENBLAS_NUM_THREADS=4; навчання також
обмежується через threadpoolctl. Попередні ноутбуки запускати не потрібно.

Зовнішні оцінювані періоди: 6–9, 10–13, 14–17. Кожен має два внутрішні
часові зрізи для вибору C, конфігурації бустингу та out-of-time прогнозів
для калібратора. Опора очищення сум і модельні перетворення навчаються
заново в кожному внутрішньому й зовнішньому зрізі.

Файли для перегляду:

- `protocol.json` — правило, зафіксоване до нових результатів; несумісний
  протокол не перезаписується автоматично.
- `strategy_summary.csv` — одна таблиця всіх стратегій: дохід, приріст до
  «завжди» й постійної train-ймовірності, три періоди, log loss/Brier/AUC,
  сценарій без змінених USD-сум та кількості оцінених спорів.
- `strategy_periods.csv` — повні метрики кожного зовнішнього періоду.
- `C_grid_summary.csv`, `C_grid_periods.csv` — діагностика C=0.01/0.1/1/10/100.
- `outer_choices.csv`, `inner_candidate_periods.csv` — як визначені параметри
  кожного зовнішнього прогнозу.
- `calibration_status.csv`, `calibration_oof.csv` — обсяг калібрування,
  його коефіцієнти й часові межі базових навчальних частин.
- `selection.json`, `run_evidence.json` — вибір, хеші й фактичний журнал
  відкриття вхідних CSV. Audit hook блокує інші таблиці outputs і
  dataset/validation/test/unknown_time CSV.

Вибір за протоколом: звичайна логістична регресія з внутрішнім вибором C.
Її Score — 22 732.60 USD на 5 141 спорах; калібрована версія дає на 5.20 USD
більше. Різниця менша за зафіксований поріг практичної близькості 257.05 USD
(50 USD на 1 000 спорів), тому обрано простішу стратегію.
Цей вибір не визначає єдиного глобального C: для трьох зовнішніх навчальних
частин внутрішній підбір вибрав 10, 1 та 0.1 відповідно.

Окрема фіксована C-сітка має максимум при C=0.1: 22 776.60 USD; при C=1 —
22 762.80 USD. Це діагностика на тих самих зовнішніх періодах, не незалежне
підтвердження оптимальності C=0.1. Підбір C у цьому дослідженні не дав
переконливого приросту порівняно з фіксованим C=1.

Ці train-періоди вже використовувалися раніше. Вкладена схема не скасовує
цього знайомства з даними. Validation уже використовували для вибору в

## Що означають train, validation і test

Це три непересічні частини за часом:

| Назва | Тижні | Для чого |
|---|---|---|
| train | 0–17 | На ранніх даних визначено типові співвідношення сум. Команда надалі може навчати тут модель. |
| validation | 18–21 | Наступний період, на якому команда зможе порівнювати свої рішення. |
| test | 22–25 у цьому наборі | Пізніший період для фінальної перевірки обраного рішення. |
| unknown_time | Немає придатного тижня | Збережено окремо; не домішувати до основної часової перевірки. |

Розділення потрібне вже під час очищення: статистичні правила визначаються на ранніх даних і без переналаштування застосовуються до решти. Цей крок не означає навчання моделі. Правило test — усі придатні тижні після 21, а не жорстка верхня межа 25.

## Що змінилося після аудиту

- У train дві невизначені USD-суми, 46 000 і 11 000, стали пропусками в очищеній таблиці. Початкові значення залишилися в аудиті. Решта 13 основних колонок train/validation відповідає попередньому архіву.
- Підозріла велика сума або суперечність між двома USD-сумами більше не потрапляє в основну таблицю як надійне число. Поріг 10 000 — робочий, а не доведена максимальна сума платежу. Для `amount` він вимірюється в оригінальній валюті.
- Прапорці `source__*` стосуються початкового стану, `current__*` — кінцевого. Старі неоднозначні прапорці й співвідношення вилучено з основних таблиць.
- Повторне застосування фінальної обробки з тим самим аудитом зупиняється з поясненням. Повний повторний запуск від `dataset.csv` дозволений і відтворюваний.
- Прапорці доступності Score записано в аудит; правила підрахунку спільні для всіх.

## Межі підготовки

Нормалізація тут означає однакові назви категорій, типи та обґрунтовані правила очищення. Стандартизації до середнього 0 чи масштабу 0–1 немає: її потреба залежить від моделі. Суми для грошового оцінювання завжди залишаються в USD, без стандартизації.

Не виконано заповнення всіх пропусків, кодування категорій, балансування класів або вибір остаточних ознак. Це наступний етап команди. У `*_clean.csv` є `won`; не подавати ціль у вхідні ознаки. `dispute_id` — ключ зв'язку, а не ознака. `amount` змішує різні валюти.

Ділення на 1000, трактування `$` як USD і вилучення недодатних сум — задокументовані припущення. Вони не доводять причину пошкодження даних. Докладніше — у першому ноутбуці.

Початковий ноутбук переглядав статистику всього набору до поділу. Тому test не був повністю недоторканим. Дані містять лише історично оскаржені спори з відомим результатом; узагальнення на всі спори не перевірене. Дата отримання результату відсутня: часовий поділ за початком спору не гарантує, що його результат уже був відомий у момент наступного періоду.

## Грошова перевірка для наступного учасника

`calculate_baseline(clean, audit)` обчислює стратегію «боротися завжди»: суму `0.2 * amount_usd * won - 6` лише на `score_eligible`. Це контроль підготовки, а не навчена модель. `observed_only=True` додатково виключає відновлені та виправлені USD-суми. «Observed» не означає незалежно підтверджену істинність значення.

На validation контрольний результат — 5 324 USD на 1 666 рядках. Без відновлених і виправлених USD-сум — 5 277 USD на 1 634 рядках. Ці суми не порівнюють ефект корекції на однакових спорах: підмножини різні. Модель і baseline потрібно порівнювати на одних рядках усередині кожного сценарію. Невідомий дохід не замінювати нулем або медіаною.
